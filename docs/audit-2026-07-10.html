SSRF via unvalidated push subscription endpoint URL
api/notifications/push/subscribe/route.ts:12 Security · API
›

z.url() accepts javascript:, file://, ftp:// and arbitrary HTTP URLs. Stored endpoint is later passed to webpush.sendNotification(), which makes a raw fetch to the stored URL. An authenticated user can register a push subscription pointing to internal services (e.g. AWS metadata 169.254.169.254), triggering SSRF on every push broadcast.

Fix
endpoint: z.url().regex(/^https:\/\//, "Push endpoint must use HTTPS")
blobOpacity output range [1, 2.2] — CSS opacity clamped at 1

›

useTransform(amplitudeSpring, [0, 1], [1, 2.2]) maps to opacity values above 1.0, which browsers clamp. The aurora blob pulse effect does nothing above idle. Likely intended to drive scale or use an opacity range of [0.82, 1.0].

Fix
// If intent is opacity pulse:
useTransform(amplitudeSpring, [0, 1], [0.82, 1.0])
// If intent is scale pulse:
// rename to blobScale and apply via style={{ scale: blobScale }}
